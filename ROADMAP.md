# Roadmap

## Phase 0 — discovery and architecture

Completed in this workspace: repository/toolchain inspection, stack decision, product/architecture/data-model docs, initial migration boundary, provider interfaces, testing setup, privacy/safety constraints, whole-health product framing, sectioned multi-goal onboarding, configurable Today focus, N//XT identity, a Mind workspace, and local contracts for wellbeing, life events, and consent.

## Phase 1 — usable core

Implemented foundation: onboarding, goals, profile/unit context, optional identity fields, optional
body and biometric metric collection, local persistence, weight history, regression trend,
transparent metabolic estimates, calorie target/range, custom/demo food logging, nutrition totals,
generalized activity logging, PWA manifest/service worker, and calculation tests.

Next hardening within Phase 1: provider lookup UI with explicit network states, barcode text workflow, timezone-aware local day, user-editable custom foods, import/export, error boundaries, browser integration tests, and the first private non-scored wellbeing check-in.

## Phase 2 — personalization

Adaptive TDEE using 21–28 day windows and completeness/volatility confidence; improved smoothing; body measurements; body composition methodology; hydration; configurable dashboard; richer goal projections.

## Phase 3 — optional behavior and wellbeing modules

Wellbeing check-ins, journaling/reflection, coping strategies, fasting, medication, symptoms, appetite,
energy, recovery, and sleep as opt-in modules with safety-aware language and recurrence modeling.
Mental-health workflows remain supportive self-understanding, never diagnosis or treatment replacement.

## Phase 3.5 — context and safety

User-controlled life events, granular consent controls, export/deletion/retention controls,
configurable region-specific support resources, and observation-based longitudinal insights without
causal claims.

## Phase 4 — advanced fitness

Workout templates, strength sets/reps/load/RPE, exercise segments, custom metrics, walking/running progression, and progression analytics.

## Phase 5 — Android

Add Capacitor host; implement native barcode, Health Connect, notifications, secure storage, camera, and appropriate background sync. Request only the permissions required by enabled features.

## Phase 6 — intelligence

Weekly analysis, pattern discovery, natural-language questions, confirm-before-save natural-language
food logging, label extraction, optional photo proposals, and an AI provider abstraction. Sensitive
wellbeing, journal, medication, and life-event data require separate consent before AI access.

## Phase 7 — commercialization

Authentication, cloud sync, account lifecycle, privacy controls, deletion/export, consent, production deployment, security review, and store distribution. Billing remains intentionally deferred.
